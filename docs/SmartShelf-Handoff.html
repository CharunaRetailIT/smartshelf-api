05 — Traps

Things that cost hours here

These are the errors actually made in this session. Each one looked like success at first, which is what made them expensive.

CRLF makes scripted edits silently no-op verify output

A Python search for "…{\n --brand-teal:" matched nothing in a CRLF file, the replacement never applied, and it was reported as done. The owner saw an unchanged page. Use the Edit tool on these files, and confirm the compiled bundle before claiming a UI change landed.

A stale process will hide your fix kill by port

pkill does not match dotnet.exe on Windows. An old build held the port and kept serving old behaviour while a "fix" appeared not to work. Kill the port owner instead:

(Get-NetTCPConnection -LocalPort 7447 -State Listen).OwningProcess

Do not guess at the Minew contract read the PDF

Two wrong guesses in one session: that a barcode was required (the doc says false), and that the image data URI prefix needed stripping — a diff against the working older API showed identical code, and all speculative changes were reverted. When a bind misbehaves, diff against SmartShelf-Revamp and read Cloud Platform API V5.0.22 before changing anything.

Test writes hit real data careful

A test PUT that omitted isActive deactivated the owner's live product. It was restored, and UpdateProductDto.IsActive is now nullable and applied only when present. Treat the local database as production data — it is the owner's working store.

The procedure that worked this session: snapshot the table first, prefer guard paths that throw before writing, and where a write is unavoidable use values that change nothing functional, then restore the audit columns and diff against the snapshot. Two writes were needed to document the combination endpoints — a no-op PUT and a throwaway pairing created solely to exercise a successful delete — and both were reverted, leaving DeviceTemplateCombos byte-identical to where it started. Say in the summary exactly which writes were made and that they were reverted.

Do not trust a physical label is idle check the clock

QueueProcessorService starts with any build and, ten seconds later, activates every Pending queue whose window is open — pushing to a real label and mutating the owner's data. Queue 14 was Pending with a start time already passed in local terms, and was safe only because StartDate is compared in UTC and it was still hours away. Check StartDate against date -u before starting a scratch build, not against local time.

:host ::ng-deep fails in overlays know this

Dialog content renders in the CDK overlay, outside the host element, so host-scoped deep selectors never match. The pattern that works here is .dlg-shell ::ng-deep, with tokens declared on :host, .dlg-shell.

Minew and EF gotchas reference

Minew signals failure with a code field while still returning HTTP 200 — always inspect it; errors arrive in Chinese (数据不存在 no data, 模板不存在 template missing, 54015 gateway offline, 成功 success). EF Include on a required navigation emits an INNER JOIN and silently drops rows. SQL Server collation is case-insensitive but C# == is not. PrimeNG 19 renamed .p-button/.p-highlight to .p-togglebutton/.p-togglebutton-checked.

curl is an alias for Invoke-WebRequest shell

In PowerShell, curl -H fails with a Headers binding error. Use the Bash tool for curl, or curl.exe explicitly.

A bodyless POST answers 411, not 404 shell

curl -X POST with no body sends no Content-Length, and Kestrel rejects it with 411 Length Required before routing. Three endpoints looked broken for a minute because of it. Send -H "Content-Length: 0". The same run also proved the route was wrong — the queue controller is api/queue, singular, not api/queues. Read the [Route] attribute rather than guessing the plural.
